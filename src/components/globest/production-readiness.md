# iHBH 客户界面与生产准备审计

日期：2026-10-25。正式域名由项目方提供：ihbh.kopiagent.ai。本轮未改域名、发布、购买服务、访问客户私密记录、发送评论、开播、请求摄像头、签到或支付。仅静态审计，不修改访问控制、密钥或交易逻辑。

## 本轮接线与数据证据
- 底部导航：/live，视频图标、中文名称及 NavLink 当前页状态；/game 路由与游戏数据保留。
- 直播：/live 只渲染 LiveDiscovery；旧 LiveHall、Stories、Streams、固定聊天组件不再由该页面导入。12840/6320 来自 liveHallData.js；2.4K watching 来自 LiveStreams.jsx；LiveChat.jsx 随机生成固定消息。这些不是生产直播证据，已从客户直播页移除，原代码与数据保留。
- LiveRoom 作为房间登记，现有 LiveBroadcast Actor 为信号连接；登记的 status=live 不宣称已核实推流，播放状态只在实际收到帧或 video playing 后确认。进入房间是显式用户操作；默认静音、原生播放和音量控件、可用时全屏、退出与重连；聊天及商品面板如实标未接入。
- 关注：未发现独立持久化关注实体；预告：LiveRoom 仅 live/ended，无预告字段；回放：无录制字段或房间录像关联，不能把 ended 作为可播放视频。三个入口可切换查看状态，但不伪造持久化成功。
- GlobalProduct 目录：查询、中文检索、分类、美元参考价格筛选、服务端排序、每页12款与游标加载；详情读取已有目录字段；外链限制为 HTTPS Amazon/短链入口，仅说明前往商家查看购买。未对商家网站逐条验价、验货或验证图片授权，因此不保证数据实时性。
- 删除原首页 GlobalHighlights 固定汇率、推算 HBH 奖励及“积分可抵扣”展示；不改底层积分、定价和兑换逻辑。外部商品不接本平台购物车；原自营 Product 目录和购物车未修改。
- LocalListing 仅查询 published 刊登信息。未新增评分、评价量、距离、地址、营业时间、时段或折扣证据。详细地址/营业时间不在现有字段中，详情明确缺失。手动区域含新加坡实际区域及中英文别名，不请求定位。
- 12家 localLifeData 静态示例单独放入折叠演示区，每卡显著说明不可交易；不展示静态评分/销量/距离/折扣/可约时段。旧 BookingFlow 与 LocalOrders 不再接入该发现页，原本地缓存和任何实体记录均未删除。
- 公开只读汇总查询：GlobalProduct 1000，published LocalListing 0，status=live LiveRoom 0，VideoPost 0。该查询不读取记录内容；是当前汇总快照，不等于视频连通性或商品真实性验证。连接检查结果：当前无授权 OAuth 服务；既有 Actor 和后端函数源文件存在，不等于外部依赖已经生产验证。

## 返回量、竞态与重试
- 三个新列表使用 usePublicCollection：服务端 filter，limit=12，cursor；计数独立 count，不用加载全部记录算总数。列表按实体/完整条件/排序隔离查询缓存，旧条件结果不会覆盖另一条件；搜索350ms防抖；加载更多同步锁+请求态禁用按钮；不自动重试，失败保留数据并允许显式重试。
- 全球分类聚合单次上限100组，有缓存；移除旧“每分类取一款”的 Promise.all N+1 请求。分类超过100组时需再设计选项分页。
- 本地示例与外部静态目录不是生产分页数据，和真实服务端结果分离。
- 直播发现用实体订阅，不再运行旧 UserLiveHub 的5秒轮询；只针对房间创建/结束/删除刷新。订阅先在 effect 注册，首次查询仍由查询组件触发，尚未对极端并发快照竞态做浏览器验证。手动刷新可核实列表，房间内始终以实际信号为准。
- 重复提交：本轮不新增交易、关注、评论或预约写入入口。直播重连可能短时间重复点击，但每次 effect 清理旧连接，未测试快速重连压力。

## 上线阻断项（未修复，需单独授权）
1. **实体访问控制**：Product/GlobalProduct 的管理写限制、LiveRoom 的主播所有者/管理员写、LocalListing 的已发布/所有者/管理员读规则在代码中存在。MemberProfile.jsonc 未配置 RLS，含会员与支付关联字段，是必须补齐并进行匿名/跨用户验证的阻断项。LocalListing 的所有者更新分支涉及可变 approval_status，需在可信服务端保护审核字段并验证不可自行发布；本轮未扩大或改写权限。
2. **订单隔离**：PurchaseOrder/ShipOrder/Ticket 规则按创建者/管理员区分，不是商户/组织 tenant_id 成员隔离。LocalOrders 当前是浏览器体验状态，无服务端订单隔离，且原实现按计时推演履约状态，不能作为真实订单；已从该发现页撤下。需建立商家身份、订单归属、服务器查询约束并进行跨租户负面测试；未读取订单数据。
3. **价格和库存**：Product 无库存字段；CartPanel/ProductPay 的金额与体验订单由客户端计算。pointsLedger spend 接受客户端 points/sgd，未与商品/服务器订单金额核对；账本幂等采用先查再写与事后去重，不是原子唯一约束或事务，不能据此承诺并发余额安全。上线交易前需服务器定价、库存锁、原子扣减/幂等以及退款对账，本轮不改规则、不执行扣款。
4. **支付回调**：stripeMembershipWebhook 有 Stripe constructEventAsync 签名验证；未见 base44_test_checkout 自测过滤，通用会员分支没有完整事件ID持久化幂等、订单/金额/币种/应用归属核对；礼包分支有部分金额/币种/price核对及会话检查，但不证明并发幂等。需单独修复并用测试环境回放验证。未调用 Stripe、不读密钥、不改函数。createMembershipCheckout 接受客户端 returnUrl；createGeneCellCheckout 硬编码原域名，不使用可信返回地址头；均是上线前须处理的问题，按本轮不改支付与域名要求原样保留。
5. **直播容量与安全**：LiveBroadcast Actor 硬上限10连接；主机向观众WebRTC直连，只有STUN，没有已配置TURN/SFU/CDN或录制服务的证据。JPEG兼容帧有96000字符及400ms间隔限制，但不等于直播CDN或聊天限速。Actor 无聊天协议、消息审核和聊天限流。LiveBan 管理记录未在 Actor host_start 中检查，禁播的服务端强制执行与现有观众终止需审计。尚未验证信令滥用控制、连麦授权和主播重连生命周期。
6. **预约与履约**：无真实商家时段库存、预约确认、服务端本地订单、退款和通知能力；不得开放团购付款或声称预约成功。需要已核实商户资料、服务规则与协议配置。
7. **监控与备份**：源代码可见部分 console.error，不等于生产告警、全链路监控、审计日志保留或备份。当前外部连接检查没有监控服务连接；平台侧日志保留、数据库备份策略、恢复演练、RPO/RTO 未核实，须由运营确认。未访问运行日志或客户资料。
8. **上线服务配置**：需要直播TURN/SFU/CDN与容量目标、聊天室认证/审核/限流、关注/通知、预告和回放来源、商家预约订单后端、服务器库存/支付幂等、监控与恢复策略。没有购买或请求任何服务授权。
